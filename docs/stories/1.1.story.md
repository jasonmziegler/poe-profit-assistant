### Project Structure Requirements

Based on unified-project-structure.md, the following directory structure must be created:

- `app/` - Next.js app directory with layout.tsx, page.tsx, globals.css, and api/ subdirectory [Source: architecture/unified-project-structure.md]
- `components/` - React components with dashboard/, ui/, and layout/ subdirectories [Source: architecture/unified-project-structure.md]
- `lib/` - Core logic with api/, analysis/, db/, cache/, stores/, types/, and utils/ subdirectories [Source: architecture/unified-project-structure.md]
- `data/` - Local data storage for SQLite and cache files [Source: architecture/unified-project-structure.md]
- `tests/` - Test files with unit/ and integration/ subdirectories [Source: architecture/unified-project-structure.md]

### Environment Configuration

Required environment variables as per development workflow:

- `NEXT_PUBLIC_APP_NAME="POE Profit Assistant"`
- `NEXT_PUBLIC_API_URL="http://localhost:3000/api"`
- `ENCRYPTION_KEY` - 32 character random string for session security
- `LOG_LEVEL="debug"` for development [Source: architecture/development-workflow.md#required-environment-variables]

### Coding Standards

- All functions must have explicit TypeScript types, no `any` allowed [Source: architecture/coding-standards.md#critical-fullstack-rules]
- Components use PascalCase naming (e.g., `OpportunityCard.tsx`) [Source: architecture/coding-standards.md#naming-conventions]
- API routes use kebab-case (e.g., `/api/characters/fetch`) [Source: architecture/coding-standards.md#naming-conventions]
- Functions use camelCase naming [Source: architecture/coding-standards.md#naming-conventions]

## Testing

### Testing Standards

- **Test Organization:** Tests must be organized in `tests/unit/` and `tests/integration/` directories [Source: architecture/testing-strategy.md#test-organization]

- **Unit Tests:** Focus on individual functions and components with explicit TypeScript types [Source: architecture/testing-strategy.md#unit-test]
- **Integration Tests:** Test API routes and database interactions [Source: architecture/testing-strategy.md#integration-test]
